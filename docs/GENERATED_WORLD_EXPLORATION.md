# 生成画面游览实现 — 2026-09-10

最新实现已增加主动相邻视角预生成：进入世界后后台准备前方、左侧、右侧，玩家的探索方向优先。已生成视角保存在当前 session 的独立图谱中，浏览器在相邻视角之间保留绝对相机位置切换，回看直接使用原缓存。**这是连续视角探索原型，仍不是完整、校准的开放世界。**

## Biome / Waypoint 启发后的预热与持续扩展

已核对 Biome 源码，参考提交 `e3bc3715ba32f787d1f9719f183d4fddf6917cbe`：

- [初始化阶段](https://github.com/Overworldai/Biome/blob/e3bc3715ba32f787d1f9719f183d4fddf6917cbe/src/stages.ts)区分模型加载、预热、初始化帧、session.ready。
- [输入循环](https://github.com/Overworldai/Biome/blob/e3bc3715ba32f787d1f9719f183d4fddf6917cbe/src/hooks/streaming/useInputLoop.ts)逐帧发送控制输入；[呈现调度](https://github.com/Overworldai/Biome/blob/e3bc3715ba32f787d1f9719f183d4fddf6917cbe/src/hooks/streaming/useFramePacer.ts)以新鲜帧优先，避免靠积压视频制造平滑。
- [官方 Waypoint 模型卡](https://huggingface.co/Overworld/Waypoint-1.5-1B-360P)描述的是基于历史帧和键鼠控制的交互视频生成，并非保证物理精度的场景模拟器。没有把其预热误称为“离线生成完整三维地图”。本项目没有复制其代码，也没有把 LingBot 偷换成 Waypoint。

本项目在当前 LingBot + 深度表面路径上采用自己的预计算策略：

1. **进入前准备**：默认至少 24 个已保存视角，且按条件相机位姿计算的起点环视最大角间隔不大于 0.40 弧度（这不是对生成内容的几何一致性认证）。先完成环视分支，再准备附近路径。满足条件才开放「进入游览」，初始化中有数量与覆盖进度；已缓存场景可以快速恢复。
2. **持续向外扩展**：完成一个节点就自动补充后续任务。无需按键触发。进入后以当前所在视角为中心，优先附近、朝前的候选路径；直接方向需求优先于推测任务。
3. **更积极的预算**：每源场景默认 192 个视角（原 48），最多 8 个排队/执行任务（原 4），GPU 仍单任务运行。`CARINA_EXPLORATION_BUDGET` 可设 24–1024，`CARINA_WARMUP_VIEWS` 可设 24–128，预热目标不超过总预算。达到预算就保留缓存并停止新增。
4. **前台活动约束**：可见世界每 10 秒续期一次，60 秒无续期则停止后续自动任务，避免关闭页面后无限计算。切换世界、隐藏页面或关闭主动探索会清理未开始的任务；一段已经开始的 GPU 推理仍会完成并保存。

验收结果：真实酒馆在不发送移动命令的情况下从 8 个缓存视角推进到 21/24，再完成按位姿计算的 100% 环视覆盖，开放进入；随后继续扩展到 34 个视角。浏览器已显示沉浸探索状态。初始化包含起点环视纹理资源的加载，减少首次快速转身的取图等待。当前 188 项 TypeScript 测试和构建通过，数值相机 Python 测试通过。

预生成比原版积极，但吞吐量没有凭空提高。当前每段仍需完整条件推理和深度重建；快速持续移动可能超过生产速度。环视闭环可能有外观漂移，相邻深度仍是独立相对尺度。这些与真正实时流式模型、标定后的连续三维场景仍有差距。

## 主动探索增量

- LingBot 新增 `/v1/explore`，使用 `camera_path.py` 写出逐帧 OpenCV `poses.npy` 和 `intrinsics.npy`，不再用固定 example trajectory。向前/侧移步长为 0.55，左右转动为 0.32 弧度（约 18.3°）。这些是条件输入，不代表重建结果达到了精确几何标定。
- 每条分支使用指定父视角的图片与确定性随机种子。请求不会覆盖原世界 still。输入相机轨迹不等于持久 KV 会话；模型仍每段独立生成。
- 每世界、每源画面版本默认最多 192 个视角，最多 8 个排队/生成任务，全局串行推理。需求方向优先；前台生成占用服务时，预生成返回繁忙并退避。已开始的推理无法被此调度器中断。
- 「主动探索」开关按世界保存在浏览器。关闭会清除尚未开始的排队任务；已经运行的一段完成后保存。它独立于世界时间的运行/暂停。
- 图片生成结果还会单独保存在 `${CARINA_DATA_DIR}/exploration-frames/`，深度重建失败时重试复用它，避免重复 GPU 推理。原图与相邻节点写入 `${CARINA_DATA_DIR}/exploration/<worldId>/atlas/<rootHash>/`。读回原地点不会重生成，也不覆盖旧版本。浏览器最多保留 32 份 GPU 视角资源，起点环视资源优先保留以支持快速转身，磁盘缓存继续保留。
- 服务接口：`GET .../exploration/atlas?root=<hash>`、`GET .../exploration/nodes/<id>?root=<hash>`、`POST .../exploration/prefetch`。继续使用现有 session 鉴权和身份校验。
- 已实测真实酒馆自动产出 3 个相邻视角，再扩展到第二圈；浏览器可从 0° 连续转到 17.6°、35.3°，超出原单视角边界。
- 首组日志中相邻任务依次在 21:40:34、21:40:44、21:40:53 返回；这不是逐帧响应速度，也不是完整端到端性能基准。输入仍由本地相机逐帧处理，遇到未准备内容时仍需等待覆盖扩展。

## 本轮实现

- 独立 CPU 深度服务使用 Depth Anything V2 Small，生成图片反投影成 160 列的网格。原始图片作为不受额外灯光影响的颜色纹理，保留生成画面的外观。
- 浏览器逐帧运行相机，输入不调用管家或图像模型。统一鼠标灵敏度、归一化斜向移动、指数加减速、鼠标锁定、沉浸视口、退出/失焦清键。
- 视觉重建与碰撞代理分开。按钮可查看已有代理，估计深度不会冒充权威碰撞数据。局部游览移动的是观察相机，不修改游戏角色或物体。
- `/v1/sessions/:worldId/exploration` 优先使用当前观测，再尝试固化贴图，最后可恢复 sidecar 中同一 world ID 的已有画面。新图片按哈希重建，失败保留上一幅画面。
- 本地 `${CARINA_DATA_DIR}/exploration/<worldId>/surface.json` 保存图片、深度、捕获基准。已有缓存不依赖深度服务，也不随 runtime 玩家位置漂移。不同 session 的缓存隔离。
- 代理模式移动请求限制一个在途请求，合并为最新目标，避免无限堆积。

## 使用

打开应用，选已有生成画面的世界，等待首次重建，点击「进入游览」。WASD 局部移动，鼠标或拖动环顾，Tab 退出，支持鼠标锁定的浏览器也可 Esc 释放。点击「回到起点」恢复画面基准。管家文本生成后后台更新空间表面。

- 应用：`http://127.0.0.1:18790`
- 配置新增 `CARINA_DEPTH_URL=http://127.0.0.1:18791`（与生成服务共用本地入口）
- 数据目录仍为 `/tmp/carina-app-data`，未修改原世界快照。此目录是开发临时目录，长期使用应设置持久目录。
- 独立深度脚本：`sidecars/depth/server.py`
- GPU 机器部署：`/home/wuyw/builds/lingbot-world-v2/carina_depth_server.py`
- 模型：`/data/disk1/models/depth-anything-v2-small`
- 日志：`/data/disk1/models/carina-depth-server.log`
- 深度服务只绑定 loopback，使用已有 Python 环境，在 CPU 上运行，不进入 LingBot 的 GPU 生成锁。

当前已将深度请求经 LingBot 服务转发到同机的独立 CPU 深度进程，本地共用既有 18791 隧道，不再依赖额外 18792 转发。需要单独调试深度进程时才使用：

```sh

```

应用启动时给原有环境增加 `CARINA_DEPTH_URL` 即可。没有配置或服务不可用时，已有本地重建缓存仍可读；没有缓存的世界保持观测/代理模式。

模型来源与安装方式：[Depth Anything V2 Small 官方模型卡](https://huggingface.co/depth-anything/Depth-Anything-V2-Small-hf)。需要 `transformers`、`torch`、`numpy`、`Pillow`，当前远程环境已经具有这些包。模型文件为 config.json、preprocessor_config.json、model.safetensors；默认本地读取，不在请求时自动下载。

## 明确限制与后续阻塞

深度是相对深度，用 2–16 的显示尺度反投影，不是米制测量。相机内参仍使用现有应用的假定视场，不是从 LingBot 导出的真实内参。只有前向表面，没有背面、遮挡后物体或全景覆盖。因此每个视角限制观察位移半径 0.65，视角范围随画面覆盖变化。相邻视角准备好后可以继续切换和推进；没准备好时仍保留覆盖边界。这不能计为无限开放世界验收通过。

没有把该表面写入原 GLB 导出或冻结按钮。现有冻结/导出仍是原来的代理几何流程，不能理解为新画面已经变成完整建模资源。普通三角网格在深度断层处仍可能拉伸；这一路径不适合作为最终建模资产。

要满足原需求，下一步必须改变生成服务接口，而不是继续调相机：

1. 数值相机轨迹已接入；仍需相机标定、持久生成状态、相邻视角重投影/闭环一致性校验。目前换视角可能有形变或接缝，后续不能仅靠界面平滑遮掩。
2. 多视角重建与坐标对齐，得到覆盖连续路径的几何或 Gaussian 场景；生成任务在玩家到达边界前异步补充相邻区块。
3. 从已验证几何建立独立碰撞和导航表示，再接回游戏角色、交互物体和运行时。用返回原地点不变、断开模型仍能走、门与碰撞一致来验收。
4. 提供有质量标识的几何/贴图资产导出，保留来源与校准状态。

只增加模型调用频率或把单张图铺满盒子，无法补上这些能力。
