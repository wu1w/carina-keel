# 三维区块组装与流式游览（2026-09-10）

本次把默认主视口从切换生成图片/单视角深度网格，改为渲染持久化 GLB 区块。它是**根据世界模型画面提取语义后进行参数化资产组装的原型**，不是已完成的高保真 image-to-3D / 多视角重建系统，也不是传统网游服务端。

## 实际运行链路

1. 用户打开 session，POST `scene/prepare`。先读取 `scenes-v2/<worldId>/recipe.json`，命中后不调用任何模型。
2. 首次准备复用世界模型生成的参考画面，通过现有管家视觉模型提取有界 JSON：世界标题、材质色彩、密度、资产类别。现有 exploration loader 可从缓存、世界包或 depth sidecar 取得参考；此流程不把它的估计深度当作几何或碰撞真值。
3. `src/world-scene/geometry.ts` 用确定性种子与参数组装酒馆、屋顶、梁架、地板、吧台、桌凳、木桶、酒瓶、树木、石块。模型不生成可执行代码。当前资产类别有限，空间布局仍主要由模板控制。
4. 先生成 24×24 米起始区块。几何、碰撞、独立资产归档和绘制用 GLB 全部写盘，再发布元数据。浏览器下载并上传完成后开放游览。
5. 浏览器每 500 ms 提交位置与预生成开关，服务器保持 30 秒预取租期，以玩家所在块为中心准备半径 2 的 5×5 邻域。区块间有固定对齐的通路；循环在每块之间让出事件循环。不需要再次调用 LLM 即可组装新块。
6. 相机移动、归一化斜向速度、加减速与滑墙碰撞全部在本地执行；不发送旧 `player.act` 命令，也不等待图像生成。未载入区块边界会挡住玩家。新块只追加，不替换已有几何，也不重置相机。
7. 模型或连接故障不会卸载已有三维区块。服务器缓存重开通过离线测试；应用仍须运行。不是浏览器离线 PWA。

## 性能措施

- 同一材质合批，单块通常少于 10 个绘制批次，保留原始资产节点供导出编辑。
- 运行时传输二进制 GLB，不发送大规模浮点 JSON。
- 每次最多两个区块下载，上传任务在 RAF 中按约 2 ms 的时间预算拆分。该预算在网格之间检查，不能硬性抢占单次驱动上传。
- 只下载邻域，超过 3 块距离即释放 GPU 缓冲。持久化资产不随显存淘汰而丢失。
- 远距离及视锥外区块跳过绘制；绘制循环缓存 uniform locations。像素比上限 1.5。
- 服务端元数据只返回附近块，另返回已保存总数。碰撞接口不重复读取整个 GLB。
- 首次模型参数提取与后续组装成本分开显示/记录。当前没有持续调用世界模型去建造全新高质量资产；后续速度主要来自模型参数和已有资产模板复用。

## 导出与持久化

目录：`CARINA_DATA_DIR/scenes-v2/<worldId>/`。

- `recipe.json`：冻结参数、参考图哈希、确定性种子、初次规划耗时。
- `x,z.glb`：绘制合批后的区块网格，节点使用全局米制坐标。
- `x,z.json`：区块位置、碰撞、三角形数和几何组装耗时。
- `x,z.assets.json`：生成时的独立网格归档。导出读取它，不重新随机生成、也不调用当前模板重建旧世界。

`GET scene/export` 输出含独立资产节点的合并 GLB。`GET scene/archive` 输出区块 GLB、碰撞元数据与 recipe 的 ZIP。资源包不是原有 `.carina` 导入格式，不能宣称已实现该格式的完整世界往返导入。

v1 是本次迭代中已留存的早期组装缓存；v2 加入闭合屋顶山墙、梁架与酒架细节。v1 保留不删除。开发时为已测试的“真实酒馆”复制了其初次模型 recipe 到 v2，避免重复推理，资产重新生成并独立保存。

## 本机验证

实际服务为本地 daemon + 现有 Grok 接口 + 缓存的 LingBot 参考画面。记录见 `benchmarks/scene-streaming-2026-09-10.json`。

- 初次模型规划：44,214 ms（包含取得缓存参考与模型请求，不代表通用建模服务性能）。
- 实测 25 个区块的几何组装：约 0.065–1.665 ms/块，不包括 GLB 编码、磁盘写入、网络下载和 GPU 上传。
- 主动前移预取中心后，已保存区块由 25 增至 40；起始 GLB SHA-256 保持不变。
- 起始绘制 GLB：133,848 bytes。
- 导出：3,859 个独立节点，6,597,176 bytes；本次 HTTP 获取约 92 ms。
- 资源 ZIP：4,015,321 bytes。
- in-app 浏览器小视口和沉浸视口实际看到 RAF 帧间隔 P95 约 9–11 ms，上传观测峰值约 0.5 ms。这不是 GPU 时间、输入到光子的延迟，也不是网络 RTT；不能外推成所有设备的帧率保证。
- 193 项 TypeScript 测试通过，build 通过。新增测试覆盖确定性几何、索引/法线、合批三角形守恒、通路碰撞、并发准备合并、模型离线重开、导出、滑墙、未准备边界和区块接入后连续行走。

## 尚未完成的关键产品能力

当前是流式游览底座，不应当宣称已达到完整开放世界游戏效果：

- 画质仍受参数化资产库限制；没有高保真纹理、真正的图像/视频到多视角一致三维重建、完整地形、LOD 资产链或阴影系统。WebGL 使用简单光照和雾，不是 Lumen / DLSS。
- 管家原先的命令与世界快照仍使用旧 SceneObject/runtime 数据。自然语言校准、拾取、门、NPC 和网络权威物理尚未接入新三维场景。视口禁用旧 E/G 交互，避免操作不可见的旧对象；界面明确说明该边界。
- 新块变化主要来自确定性种子和初次模型 recipe，不是后台不断生成全新的高质量三维资产。需要下一步接入真正的资产生成/重建工作器，并以同一 scene manifest 接管图谱、碰撞、导出和修改事务。
- 主视口不再播放生成图片，因此现有管家生成画面不会自动覆盖已落盘场景。下一步应增加模型修改提案 → 校验 → 受影响区块事务提交，而不是重新覆盖整个世界。
