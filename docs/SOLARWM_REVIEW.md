# SolarWM 对 Carina 的适用性审查

日期：2026-09-11。结论：值得做小规模验证；优先复用相机/尺度标注与质量控制，暂不替换正式3D运行时。仅完成论文、文档和源码审查，没有下载模型、GPU实测、安装依赖或启动训练。

## 确认项目与版本

官方项目是 Junchao-cs/SolarWM，README公布开源日期2026-09-03；论文v1为2026-09-02。主仓审查commit `a3a3fac16466102a2b97df867f7703df7172cb2a`；通过其.gitmodules取得数据引擎 `Enderfga/solar-wm-data`，commit `d1c6e7213d0836c9c5de4d586a4963e5f688485e`。检索也返回solarwm-data命名页面，实际代码以主仓子模块链接为准。

源代码只克隆到/tmp/carina-solarwm-review和/tmp/carina-solar-data-review供只读检查，没有执行外部安装/训练脚本。

## 1. 它解决什么

SolarWM是相机可控、长时自回归的视频世界模型框架。公开5B路线包含双向适配、因果初始化、蒸馏阶段；其他较大模型的阶段开放程度不同，不能视为全部已可实时推理。

本项目最相关的两部分：

- 相机控制生成：初始图像、文本和相机轨迹驱动连续视频；有潜力减少手工逐视角提示与生成参考。
- 数据引擎：将视频整理为帧对齐的图像/视频、米制c2w、逐帧内参、静态场景描述、质量分数及来源。可以借鉴统一接口、处理缓存和失败筛选。

其三阶段“简化”首先针对世界模型训练，不直接意味着三维资产抽取步骤变少。

## 2. 不能把视频输出误作资产输出

已检查的Wan5B Stage2文档明确发布生成MP4、对比MP4、相机npy及运行manifest。相机文件来自输入的权威轨迹，不是对生成画面重新测出的轨迹。camera conditioning存在，不代表每帧内容严格满足输入投影关系。

在所审查的标准推理输出路径中，没有直接输出带UV/PBR的GLB、对象拆分、碰撞、可编辑光源或完整空间记忆。数据引擎的规范clip也主要是video、poses、intrinsics、prompt、meta；gt_depth只在原始来源具有真值深度时提供。

长时生成连续性也不等于“离开酒馆再回来桌子完全不变”，更不等于物理交互。论文的公开因果实验保持场景文本固定，变化控制来自相机轨迹；不能据此推断任意自然语言实时编辑或拾取物体已完成。

## 3. 真正能简化的几何前处理

数据引擎组合Pi3X结构、MoGe-2尺度深度与VIPE相机估计/优化；有已知轨迹时保留轨迹，并通过尺度对齐处理。它不是独立发明的可编辑资产生成器，而是将多项前处理整理为可复用流水线。

Carina可借鉴：

1. 参考帧与相机/内参严格帧对齐，采用统一c2w约定。
2. 未知位姿视频使用其估计链路；已知引擎相机先直接保留，不重复跑完整SLAM。
3. 用控制轨迹与生成画面重新估计/重投影的一致性检查识别漂移，不能仅用输入轨迹宣称真实尺度精确。
4. 输出结构置信度、坏帧和失败原因；通过检查的结果才进入融合/重建。
5. 昂贵的物理预处理与轻量的选择/索引分离，改筛选条件不重复GPU计算。

仍需Carina补齐：跨视角融合/网格或splat生成、对象拆分、UV与材质去光照、碰撞、拓扑清理、LOD、导出、局部编辑和版本提交。世界模型生成视频中相互矛盾的物体不能靠尺度标注自动修复。

## 4. 防止假验收的具体源码证据

- `configs/models.yaml` 默认 `dry_run: true`；README明确默认适配器产生能通过结构检查的占位输出。必须真实模型运行并检查图像/几何，不能以validate_dryrun通过作为3D能力证据。
- Stage2配置480×864、fps=16、四步采样、每块3个latent；是配置参数，不是5070 Ti的墙钟性能报告。
- 已审查示例按完整camera-backed horizon运行并写MP4；存在流式VAE解码实现，但不能把它当现成的浏览器键鼠/WebRTC交互服务器。
- 公开文档的single GPU命令未给出5070 Ti显存与端到端交互延迟。长时输出也不能证明80–120ms输入到显示。

## 5. 5070 Ti 的可行性边界

最小候选是5B Stage2，不从14B/22B/33B或训练开始。粗略仅5B参数×2字节约10GB十进制权重；这不是总显存估算，还需文本编码器、VAE、KV缓存、激活和临时缓冲。16GB显存能否运行及速度均待实测，不能与重建/渲染/烘焙同时满载。

Wan发布验证环境使用PyTorch2.5.1/CUDA12.4与FlashAttention等组件。5070Ti上的架构兼容、Windows或WSL环境、算子可用性需单独探测；不能将旧CUDA环境原封不动认定兼容。若需要量化/offload，要标明它改变了官方基线，并重新测画质/延迟。

项目代码Apache-2.0不覆盖所有权重/数据/依赖许可；模型入口存在访问条件。小实验只获取必要权重和自有测试输入，不下载整套25TB训练集，不训练、不申请数据或接受新访问协议。

## 6. 最小酒馆实验，避免再次盲目迁移

实验A优先：拿已有真实三维酒馆渲染10秒已知相机视频，走出/回看、侧移与绕物三种轨迹，跑数据引擎的真实几何链，比较估计轨迹/尺度与引擎真值。记录帧重投影误差、尺度误差、失败比例、GPU秒和峰值显存。先证明测量链可信。

实验B：同一首帧/场景文本/相机轨迹，SolarWM与现有世界模型生成短片，使用同一几何检验。关注转身回看、桌子背面、新显露区域、门窗位置；把漂亮但几何不一致的帧拒绝掉。

实验C：只将通过几何检验的一小段转换成可融合的候选，用独立重建/UV/材质步骤固化，导入当前运行时，从未参与生成的视角检查。比较“生成+处理+人工修复”的完整时间，不只比较推理速度。

暂定选择：SolarWM可作为后台参考/待探索区域生成候选；数据引擎作为几何观测前处理候选。已固化酒馆、游戏控制与导出契约继续由稳定3D世界管理。只有B/C证明资产一致性与总成本改善后，才扩大范围。逐帧神经外观增强不是SolarWM已证明的DLSS式用途。
